# RAZE OS Home — What The Buyer Gets

## Acquisition Model

The intended transaction is an **exclusive acquisition of the complete RAZE OS Home project**.

The public repository is a showcase only. The production source code and private project materials are transferred separately to the buyer as part of the completed transaction.

The final purchase agreement controls the exact legal scope of ownership and intellectual-property transfer.

---

## Included In The Intended Transfer

### 1. Complete Application Source

- complete Android application source code
- Kotlin source and project structure
- application modules and internal components
- UI implementation
- kiosk implementation
- navigation and page structure
- application state and persistence layers
- supporting utilities and internal services

### 2. Build & Project Infrastructure

- Android project configuration
- Gradle configuration required by the project
- source/resource structure
- build-related project files
- relevant scripts and project tooling that form part of the application
- configuration templates required to continue development

Private credentials and personal secrets are not transferred as reusable seller credentials; the buyer configures their own accounts and credentials.

### 3. Smart-Home Integrations

The intended project transfer includes the existing integration implementation around the systems currently used by the project, including:

- eWeLink
- Sonoff devices
- camera / RTSP workflows
- human / presence detection
- Xiaomi
- Dreame
- Telegram
- voice-assistant functionality
- room and occupancy systems
- automation infrastructure

The buyer receives the implementation. Third-party accounts, cloud subscriptions, hardware and third-party licenses remain subject to their own ownership and terms.

### 4. Reasoning & Agent Infrastructure

- autonomous reasoning implementation
- reasoning event flow
- supported action infrastructure
- action candidate handling
- action execution paths
- action-result persistence
- verification flows
- reasoning-to-household-event integration
- agent/system functionality

The current architecture is designed around the sequence:

```text
Context → Evidence → Reasoning → Supported Action → Verification
                                      ↓
                                  User Feedback
                                      ↓
                              Scoped Knowledge
```

### 5. Household Learning

- Household Learning implementation
- reasoning insight presentation
- correct/incorrect feedback flows
- natural-language feedback handling
- feedback target context
- structured decision knowledge
- narrow-scope knowledge storage
- knowledge lookup used by later reasoning

The learning layer is designed to influence decision knowledge without replacing deterministic sensor truth.

### 6. Security Systems

The intended transfer includes the implemented security workflows around:

- face recognition / authorization
- sensitive-operation face verification
- camera human detection
- Telegram security notifications
- image/evidence delivery
- emergency countdowns
- phone-call flows
- cancellation evidence
- security context
- occupancy/presence

### 7. Existing Product Assets

- UI assets used by the application
- project-specific visual resources
- relevant local assets
- existing documentation
- architecture documentation maintained with the project
- existing presentation material where agreed as part of delivery

### 8. Knowledge Transfer Material

The showcase documentation is intended to give the buyer a high-level map of the system before acquisition, including:

- architecture
- feature surface
- integrations
- real-world scenarios
- reasoning and learning model
- security boundaries
- kiosk/UI structure
- technical overview
- buyer due diligence notes

Private source-level documentation and configuration material can be included in the actual transfer where it forms part of the agreed project package.

---

## Not Included

The following are **not** intended to be transferred as the seller's personal assets or credentials:

- personal API keys
- personal passwords
- private signing keys unless separately and explicitly agreed
- personal cloud accounts
- personal Google/Apple/Microsoft or other identity accounts
- personal Telegram account or bot ownership unless separately transferred and legally appropriate
- personal eWeLink/Xiaomi/Dreame or other vendor accounts
- private household data
- private camera recordings
- personal messages and private communications
- physical smart-home devices owned by the seller
- unrelated personal software or projects
- the seller's personal identity or accounts

Where the project requires third-party services, the buyer should create or transfer appropriate accounts under their own ownership and credentials.

---

## Third-Party Rights & Dependencies

The acquisition transfers only rights that the seller owns and is legally able to transfer.

The project may use third-party open-source libraries, SDKs, APIs, device platforms, cloud services and other components governed by their own licenses or terms. Those rights are not magically transferred by selling this project.

A private dependency and licensing review can be performed as part of serious buyer due diligence.

---

## Branding & Commercial Use

The intended exclusive acquisition allows the buyer, under the final agreement, to:

- replace the RAZE OS branding
- introduce a new product identity
- modify the architecture
- add or remove integrations
- commercialize the software
- create derivative products
- redistribute the resulting product
- resell the resulting product

The buyer is not expected to continue using the RAZE OS Home name.

---

## What The Buyer Is Actually Buying

The buyer is not merely buying an Android UI.

They are acquiring an existing foundation in which device integration, household state, room awareness, security, automation, reasoning, action execution, verification and learning have already been made to communicate within a real-world system.

The value is the accumulated engineering work and the time already spent making the parts cooperate.

> **The expensive part is not making one device work. It is making hundreds of moving parts understand each other without turning the whole house into spaghetti.**
